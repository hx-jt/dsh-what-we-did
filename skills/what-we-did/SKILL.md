# what we did

we代表用户与Agent。真实轮次会自动记录；普通问答不用为记日志每轮调用工具。

自动展示是有限基线，之后是增量。按 id 和 revision 合并此前仍有效片段；同一轮的开始、回复、结束是同一条记录的修订。最后一块不是完整列表，未出现不代表删除。初始省略或预算积压可主动分页查询，不让模型维护自动交付游标。

- “刚刚聊过什么”：先用有效原文与近期片段；不足时 did_list，然后 did_get。摘录可截断，源地址才是找原始会话的索引。
- “上周某天”：结合用户时区确定明确 ISO 起止，例如 Asia/Shanghai 的一天是 `2026-10-19T00:00:00+08:00` 到 `2026-10-20T00:00:00+08:00`，使用 startTime/endTime，范围左闭右开。
- “这个会话先后做过什么”：sessionId + order=asc。records 默认按 updatedAt，startedAt 表示期间开始，endedAt 表示期间结束；events 按 occurredAt 筛选、按 seq 排序。自动增量始终按持久 seq，不受晚到或时钟回拨影响。
- “更多历史”：did_list 无参数返回最近一页。继续时保留全部过滤和 limit，使用 nextCursor；不把主动查询游标当自动交付游标。查询不改变自动交付覆盖。did_get 大返回按 offset/limit 读取 JSON 片段后拼接。
- “请给原话”：did_get提供完整did元数据，不提供完整会话。replyExcerpt为空仅表示did没有可用摘录，不能推断原会话不存在、已丢失或无法恢复。sourceRefs是定位信息，不证明已经读过原文。有可用原会话读取能力才读取并引用；没有时准确说明当前工具不能直接读取全文。若用文件或ReMe补充，明确其来源，不能把文档段落冒充当时聊天原话；360字符摘录也不能逐字还原长回复。
- “为什么没显示”：可能超出展示范围、初始预算省略、增量积压、自身原文仍可见、保存已过期或存储不可用。did_diagnostics 只查指定会话。UNAVAILABLE 不是空历史；查询为空不能证明没有发生。
- “恢复长轮次”：同一 id 的开始/更新/结束合并理解，事件数量不是轮次数量。interrupted 的确切结束时间未知，不擅自补成重启时间；恢复查询不代表恢复执行原任务。
- “调整窗口”：先 did_config_get，检查 allowedFields、bounds、userLockedFields、冷却和 configVersion；did_config_update 传点路径 patch、reason、expectedVersion。版本冲突先重读。理由来自模型，不升级为用户长期偏好。保存和展示独立，扩大展示不会重灌旧窗口；按需查询新增范围。缩短保留返回待确认策略，离线用户维护才会生效/清理，不额外唤醒模型调参。

请求、助手建议、回复摘录、replied 均不是执行证明或业务成功；也不是用户同意或授权。要断言做过实际操作，核对对应工具结果或原始证据。displayTitle 是注解，不覆盖请求摘录。相邻轮次不推断归属；不自动关联任务，不替代任务账本或长期记忆。

压缩不保证摘要覆盖经历。插件检测有效历史替换后提供有预算的恢复基线，可能与摘要重复；不能声称恢复了全部细节。驻留归并只撤换插件自己的消息，原始会话账本保留。
