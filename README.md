# what we did

**we 代表用户与 Agent。** what we did 按时间线和会话整理双方的对话，帮助 Agent 掌握近期各个会话更新了什么、事项如何推进，并沿记录追踪具体交流内容。

**它是记忆模块的补充，不是记忆系统。** 记忆模块在召回短期时间线上的事务记录时，可能出现遗漏、内容错配或先后顺序混淆。did 提供按轮次持续记录、按时间和会话可查的经历索引，让 Agent 接续近期事项时，多一份可核对的记录，而不只依赖一次记忆召回。

一轮对话对应一条 did，开始、回复和结束是同一记录的更新。记录保留请求/回复摘录、时间、状态与来源，通过有限增量让其他会话了解后续更新；需要细节时，可按时间或会话定位记录，再沿来源追踪。它不依赖特定任务管理插件或记忆模块，也不修改 DSH 核心。

版本：0.1.1。独立 DSH 插件。

## 能做什么

- 自动逐轮记录，普通问答无需调用日志工具。
- 事件追加、记录持久化；按时间、会话或组合条件分页查询。
- 每个接收会话独立维护交付进度，无合格更新不追加消息；原文仍在时排除本会话重复经历。
- 保存和展示窗口独立，默认永久保存；展示、增量与驻留有字符预算。
- 配置调整有权限、用户锁定、版本检查和审计。
- 提供旧 did 导入，以及 0.1.0 回复摘录问题的定向检查和修复工具。

## 边界

请求、建议、回复摘录及 `replied` 状态均不是执行证明或业务完成确认。摘录不是完整会话，空摘录不代表原会话已丢失；来源地址不证明模型已经读过原文。

首版按时间和会话组织，不识别任务归属、不建立任务线、不生成模型摘要、不提供全文检索。默认不采集或注入 subagent 经历。

## 兼容性与安装

- Node.js >=22.19.0。
- 验证目标：DSH 0.2.1-alpha.1 / alpha.2 公共接口、Cordis 4.0.5-alpha.1；不声明兼容其他未验证版本。
- 需要宿主已配置 agents、sessions、systemPrompt、tools 与 storage-domain，迁移维护工具支持 JSON 域。

从 [GitHub Release](https://github.com/hx-jt/dsh-what-we-did/releases/tag/v0.1.1) 下载 `dsh-what-we-did-0.1.1.tgz` 和 `SHA256SUMS`。校验下载文件后，使用目标 DSH profile 的包管理方式安装本地 tgz，再启用 `dsh-what-we-did`。宿主挂载配置见 `cordis.patch.yml`；默认 `config: {}`。不因安装此插件升级整套 DSH。

已有旧 task list 内置 did 时，先关闭旧 did 录制、工具与注入，保留任务面板；纯任务版本无需这一步。同名 did 工具冲突会报错，不随机覆盖。

## 工具

|工具|用途|
|---|---|
|did_list|按时间、会话、组合条件或无条件分页查询记录/事件|
|did_get|读取一条 did 的元数据与来源地址；超长详情分页|
|did_note|可选标题注解，保留原请求，不改执行状态|
|did_config_get|查看有效配置、权限、锁定、版本与审计|
|did_config_update|在授权范围按 reason 和 expectedVersion 调整配置|
|did_diagnostics|检查指定会话的交付、积压与不发送原因|

增量片段按 id/revision 与此前仍有效的基线合并理解。最后一块不是完整列表，未出现不代表删除。用法见 [skill](skills/what-we-did/SKILL.md) 和 [系统说明](docs/system-instructions.md)。

## 配置

见 [完整示例](config.example.json) 和 [配置 schema](config.schema.json)。默认展示24小时、12条、4000字符；单批增量20事件、2000字符；自动片段驻留8000字符。字符按 JavaScript UTF-16 长度计算，不是 token。

有限保存必须明确选择 archive 或 delete。保存缩短、物理清理分开执行；配置修改不直接删除数据。模型仅可调整用户许可的字段，不能改自己的权限或绕过用户锁定。

## 升级、迁移与回退

见 [升级与离线维护](docs/UPGRADING.md)。升级 0.1.1 可防止后续回放破坏回复摘录；已经受损的旧记录需要显式检查和修复，启动时不会自动批量改正文。

迁移、修复和清理先在副本验证，处理真实域前停止对应宿主。工具不会操作任务库、ReMe或原会话文件。

## 已知限制与验证

单宿主、中小规模账本；每次持久提交重写单状态值，未做大库性能或跨进程写入验收。压缩摘要覆盖不可证明，恢复基线可能与摘要重复。驻留限制只针对插件自动消息，不限制原始会话日志或显式查询。

已有验证包含规则、真实 Cordis/Agent-loop/JSON 存储与模型请求捕获；不把模拟模型后端验证当成自然语言模型行为验收。真实模型联测的现场数据不随发布上传；公开自动化证据见 docs/VERIFICATION.md。

开发与测试环境见 [DEVELOPMENT](docs/DEVELOPMENT.md)。
